## Email уведомления

В production задайте `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD` и `SMTP_FROM`. Без этих параметров тестовый результат всё равно будет сохранён, но письмо отправлено не будет. SMTP-учётные данные должны храниться только в секретах хостинга, не в Git.

В Academy нет функциональности выдачи сертификатов, QR-проверки или генерации документов.

## Миграции базы данных

- Начальная миграция находится в `prisma/migrations/20261127130000_init/`.
- Перед первым применением обязательно выполнить `npx prisma validate` и сверить SQL с актуальной `schema.prisma` через Prisma CLI (`prisma migrate diff`).
- На тестовой PostgreSQL выполнить `npx prisma migrate deploy`, затем проверить создание всех таблиц, индексов и внешних ключей.
- Не применять миграцию к production до проверки резервного копирования и подтверждения региона размещения БД в Казахстане.

## Миграция: ограничения проверки и откат

- До появления успешного результата `npx prisma validate` и `npx prisma migrate diff` миграция считается кандидатом, не готовым к эксплуатации.
- Ручной статический аудит SQL не заменяет Prisma CLI и применение миграции к тестовой PostgreSQL.
- Prisma Migrate не выполняет автоматический down-rollback. См. `prisma/rollback/README_RU.md` и разрушительный сценарий `prisma/rollback/20261127130000_init.down.sql`.
- Не выполнять down-скрипт на рабочей базе. Для production использовать проверенное восстановление резервной копии/PITR либо forward-fix.
